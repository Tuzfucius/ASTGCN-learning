# ASTGCN 手动复现与重构指南

本文档用于指导你在当前项目中手工复现 ASTGCN 模型，并在不改变模型核心算法的前提下，对原始项目的代码组织方式进行简化和重构。

目标不是逐行照搬官方代码，而是理解官方实现的真实执行链路后，用更清晰、更容易解释、更方便扩展的结构重新组织代码。

## 1. 复现目标

本项目建议第一阶段只复现 ASTGCN 的 recent component，也就是近期历史依赖分支。

当前先不建议同时实现以下内容：

- `MSTGCN` 对照模型。
- 论文中的 daily component。
- 论文中的 weekly component。
- 多特征输入和多特征输出。
- 复杂可视化平台。

第一阶段的最小目标是：

```text
PEMS04 原始交通数据
  -> 数据预处理
  -> 图结构构建
  -> ASTGCN 模型前向
  -> 训练
  -> 测试指标输出
  -> 保存模型权重
```

对于 PEMS04，当前建议固定任务为：

```text
所有节点过去 12 个时间步的第 0 个特征
预测
所有节点未来 12 个时间步的第 0 个特征
```

输入张量形状建议固定为：

```text
(B, N, F, T) = (batch_size, 307, 1, 12)
```

输出张量形状建议固定为：

```text
(B, N, T_pred) = (batch_size, 307, 12)
```

其中：

- `B` 表示批大小。
- `N` 表示交通传感器节点数量。
- `F` 表示输入特征数，第一阶段固定为 1。
- `T` 表示历史输入时间步。
- `T_pred` 表示未来预测时间步。

## 2. 官方项目真实调用链

官方项目的核心流程可以概括为：

```text
configurations/*.conf
  -> prepareData.py
  -> 生成 *_astcgn.npz
  -> lib/utils.py
  -> model/ASTGCN_r.py
  -> train_ASTGCN_r.py
  -> experiments/
```

各部分职责如下：

- `configurations/*.conf`：保存数据路径、节点数、输入输出长度、训练超参数。
- `prepareData.py`：读取原始 `.npz`，切分历史输入和预测目标，生成训练集、验证集和测试集。
- `lib/utils.py`：加载预处理数据，读取邻接矩阵，计算拉普拉斯矩阵和 Chebyshev 多项式。
- `lib/metrics.py`：提供 MAE、MSE、RMSE、MAPE 以及 masked 指标。
- `model/ASTGCN_r.py`：实现时间注意力、空间注意力、图卷积、ASTGCN block 和完整模型。
- `train_ASTGCN_r.py`：读取配置，构造模型，训练，验证，保存权重，测试。

原始项目的主要问题不是算法错误，而是工程结构较扁平：

- 数据处理、训练逻辑、路径管理和模型构建耦合较多。
- `lib/utils.py` 职责过多。
- 训练脚本中存在大量全局变量。
- 模型和训练入口不够便于初学者逐层阅读。
- 部分代码为了同时兼容多数据集和多模型，增加了理解成本。

因此，本项目重构时应保留算法链路，简化文件职责。

## 4. 每个目录应该写什么

### 4.1 `docs/`

该目录面向读者和作业说明，不直接承担运行逻辑。

建议文件：

- `手动复现与重构指南.md`：总说明文档，解释整体目标、代码结构和手写顺序。
- `复现路线.md`：写具体复现步骤，例如先写数据层，再写图工具，再写模型。
- `数据说明.md`：解释 PEMS04 数据格式、节点数、时间步、输入输出含义。
- `模型结构说明.md`：解释 ASTGCN 的层级结构和每层输入输出。
- `训练与评估说明.md`：解释训练命令、评估指标、模型保存和测试流程。
- `重构设计说明.md`：解释为什么要拆分目录，以及每个模块的设计理由。

写作要求：

- 尽量用真实文件名和真实函数名。
- 不要只写概念，要写清楚输入输出形状。
- 遇到模型结构时，优先用流程图式文字说明。
- 不要把没有实现的功能写成已经完成。

### 4.2 `configurations/`

该目录只保存配置文件，不写训练逻辑。

建议第一阶段只保留：

- `PEMS04_astgcn.yaml`

配置内容建议按以下分组：

```yaml
data:
  dataset_name: PEMS04
  graph_signal_matrix_filename: data/PEMS04/pems04.npz
  adj_filename: data/PEMS04/distance.csv
  num_of_vertices: 307
  points_per_hour: 12

task:
  len_input: 12
  num_for_predict: 12
  num_of_hours: 1
  num_of_days: 0
  num_of_weeks: 0
  in_channels: 1

model:
  nb_block: 2
  K: 3
  nb_chev_filter: 64
  nb_time_filter: 64

training:
  batch_size: 32
  epochs: 80
  learning_rate: 0.001
  loss_function: mse
  metric_method: unmask
  missing_value: 0.0
  device: cuda
```

`README.md` 应说明每个字段的意义，尤其是：

- `len_input`：输入历史长度。
- `num_for_predict`：预测未来长度。
- `num_of_hours`：recent component 的历史小时数。
- `K`：Chebyshev 图卷积阶数。
- `nb_block`：ASTGCN block 堆叠数量。

### 4.3 `data/`

该目录只存放数据，不写 Python 逻辑。

当前建议结构：

```text
data/
```

如果暂时不移动现有 `PEMS04/` 数据，也可以先保留当前数据目录，后续再统一调整。

`data/README.md` 应说明：

- 原始数据从哪里来。

- `distance.csv` 用来构造图结构。
- 预处理后 `.npz` 包含哪些数组。

`data/PEMS04/README.md` 应说明：

- PEMS04 有 307 个节点。

- 每小时 12 个采样点。

### 4.4 `src/data/`

该目录负责数据预处理和数据加载。

建议文件：

- `preprocessing.py`
- `dataset.py`

`preprocessing.py` 建议手写函数：

```python
search_data(...)
get_sample_indices(...)
generate_dataset(...)
standardize(...)
save_dataset(...)
```

职责说明：

- `search_data`：根据当前位置向前查找历史窗口。
- `get_sample_indices`：生成一个样本的输入和目标。
- `generate_dataset`：遍历完整序列，生成所有样本。
- `standardize`：只用训练集均值和标准差标准化。
- `save_dataset`：保存为训练阶段可直接读取的 `.npz`。

`dataset.py` 建议手写内容：

```python
load_processed_dataset(...)
build_dataloader(...)
```

职责说明：

- 读取预处理后的 `.npz`。
- 只保留第 0 个特征作为输入。
- 转换为 PyTorch Tensor。
- 构造 `DataLoader`。

关键约束：

```text
输入 x: (B, N, 1, T)
目标 y: (B, N, T_pred)
```

### 4.5 `src/graph/`

该目录负责图结构计算。

建议文件：

- `adjacency.py`
- `laplacian.py`

`adjacency.py` 建议手写函数：

```python
load_adjacency_matrix(...)
```

职责说明：

- 读取 `distance.csv`。
- 构造邻接矩阵 `A`。
- 必要时支持节点 ID 映射。
- 输出形状为 `(N, N)`。

`laplacian.py` 建议手写函数：

```python
scaled_laplacian(...)
chebyshev_polynomials(...)
```

职责说明：

- 根据邻接矩阵计算度矩阵。
- 计算拉普拉斯矩阵。
- 缩放拉普拉斯矩阵。
- 生成 `K` 阶 Chebyshev 多项式。

关键约束：

```text
adjacency: (N, N)
scaled_laplacian: (N, N)
cheb_polynomials: list[(N, N)]
```

### 4.7 `src/models/`

该目录负责模型结构。

建议文件：

- `layers.py`
- `astgcn.py`

`layers.py` 建议手写类：

```python
TemporalAttention
SpatialAttention
ChebGraphConvWithAttention
ASTGCNBlock
```

职责说明：

- `TemporalAttention`：学习时间步之间的重要性。
- `SpatialAttention`：学习节点之间的动态相关性。
- `ChebGraphConvWithAttention`：结合 Chebyshev 图卷积和空间注意力。
- `ASTGCNBlock`：组合注意力、图卷积、时间卷积、残差连接和归一化。

`astgcn.py` 建议手写类和函数：

```python
ASTGCN
build_astgcn_model(...)
```

职责说明：

- 堆叠多个 `ASTGCNBlock`。
- 最后输出未来 `num_for_predict` 个时间步。
- 提供统一模型构造函数。

关键约束：

```text
模型输入: (B, N, F, T)
模型输出: (B, N, T_pred)
```

不要在模型文件里读取配置文件或数据文件。

## 6. 建议保留的算法结构

虽然要重构代码，但以下算法结构不要随意改变：

```text
输入历史序列
  -> 时间注意力
  -> 空间注意力
  -> 带空间注意力的 Chebyshev 图卷积
  -> 时间卷积
  -> 残差连接
  -> LayerNorm
  -> 多个 ASTGCN block 堆叠
  -> final convolution
  -> 未来多步预测
```

可以改的内容：

- 文件命名。
- 目录结构。
- 配置读取方式。
- 日志方式。
- 训练代码组织方式。
- 函数和类的命名风格。

不建议改的内容：

- 注意力计算公式。
- Chebyshev 图卷积逻辑。
- ASTGCN block 的主要组成。
- 输入输出形状约定。
- 训练集均值和标准差的使用方式。

## 7. 原始项目中适合简化的地方

### 7.1 暂时移除 MSTGCN

第一阶段只复现 ASTGCN。MSTGCN 可以后续作为对照实验再加入。

### 7.2 暂时移除 daily 和 weekly 分支

当前官方 PyTorch 主线主要使用 recent component。手工复现时先固定：

```text
num_of_hours = 1
num_of_days = 0
num_of_weeks = 0
```

这样更容易保证数据切片和模型输入一致。

### 7.3 简化配置格式

可以使用 yaml 替代 `.conf`，因为 yaml 更适合分组说明。

如果担心引入额外依赖，也可以继续使用 `.conf`，但建议封装到 `src/utils/config.py` 中。

### 7.4 拆分 `utils.py`

原始 `lib/utils.py` 同时包含：

- 归一化。
- 邻接矩阵读取。
- 拉普拉斯矩阵计算。
- 数据加载。
- 验证损失。
- 预测保存。

重构时应拆分到：

```text
src/data/
src/graph/
src/engine/
src/metrics/
```

### 7.5 减少训练脚本全局变量

训练入口应改成：

```python
def main():
    config = load_config(...)
    ...

if __name__ == "__main__":
    main()
```

不要在文件导入时就读取配置、加载数据和构造模型。

## 8. 分阶段验证方法

不要等全部代码写完才测试。

### 数据阶段

检查：

```text
train_x.shape
train_y.shape
val_x.shape
val_y.shape
test_x.shape
test_y.shape
mean.shape
std.shape
```

期望：

```text

y: (B, 307, 12)
```

### 图结构阶段

检查：

```text
adjacency.shape == (307, 307)
scaled_laplacian.shape == (307, 307)
len(cheb_polynomials) == K
```

### 模型阶段

使用随机输入：

```text
x = torch.randn(2, 307, 1, 12)
```

期望输出：

```text
output.shape == (2, 307, 12)
```

### 训练阶段

先只跑：

```text
epochs = 1
batch_size = 8
```

检查：

- loss 能正常计算。
- 梯度能反向传播。
- 模型权重能保存。

### 测试阶段

检查：

- 能加载 `best.pt`。
- 能输出 MAE、RMSE、MAPE。
- 预测值和真实值形状一致。
