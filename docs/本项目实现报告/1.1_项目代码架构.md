# 1.1 项目代码架构

项目采用“配置驱动 + 核心库 + 脚本入口”的组织方式。核心计算逻辑放在 `src/astgcn/`，训练和评估由 `scripts/` 调度，实验参数由 `configs/pems04.yaml` 统一管理，结果写入 `outputs/`。

## 1.1.1 目录职责

| 目录 / 文件 | 作用 |
|---|---|
| `src/astgcn/data/` | 数据读取、时间窗口构造、图结构生成、标准化与 DataLoader 封装 |
| `src/astgcn/models/` | 注意力、Chebyshev 图卷积、时空块、单分支组件、三分支融合与消融配置 |
| `src/astgcn/engine/` | 训练器、评估器、预测器与 checkpoint 保存 / 加载 |
| `src/astgcn/baselines/` | Historical Average、SVR、LSTM、GRU 等基线模型 |
| `scripts/train.py` | ASTGCN 训练入口 |
| `scripts/infer.py` | checkpoint 加载、测试集评估与预测保存 |
| `scripts/compare_baselines.py` | ASTGCN 与常用基线的统一对比 |
| `configs/pems04.yaml` | 数据集、窗口、图结构、模型、训练和输出目录配置 |
| `outputs/` | 训练 checkpoint、日志、预测结果、基线对比结果与消融实验结果 |

## 1.1.2 核心模块分工

`ASTGCN` 是总模型，负责 recent、daily、weekly 三个分支的实例化与融合。  
`ASTGCNComponent` 是单分支建模模块，由多个 `STBlock` 组成。  
`STBlock` 负责局部时空建模，顺序为时间注意力、空间注意力、图卷积、时间卷积、残差与归一化。

三者关系可写为：

$$
\hat{Y}
=
\mathcal{F}\Big(
\mathcal{C}_r(X_r),
\mathcal{C}_d(X_d),
\mathcal{C}_w(X_w)
\Big).
$$

其中：

$$
X_r, X_d, X_w \in \mathbb{R}^{B \times N \times F \times T},\qquad
\hat{Y} \in \mathbb{R}^{B \times N \times P}.
$$

## 1.1.3 工程化特征

1. 训练、推理、基线对比共用同一套数据处理与图构造逻辑。
2. 参数全部通过 YAML 配置传入，便于复现实验。
3. checkpoint、日志、预测结果与可视化结果分目录保存，减少实验间污染。
4. 消融配置通过 `AblationConfig` 控制，便于按结构因子逐项关闭模块。

## 1.1.4 代码规模中的关键量化信息

1. 核心实现目录包含 `data/`、`models/`、`engine/`、`baselines/` 四个子系统。
2. `models/` 中主实现文件包括 `astgcn.py`、`component.py`、`st_block.py`、`fusion.py`、`attention.py`、`cheb_conv.py`、`temporal_conv.py` 和 `ablation.py`。
3. 训练主入口为 `scripts/train.py`，推理主入口为 `scripts/infer.py`，对比入口为 `scripts/compare_baselines.py`。
